# CS320_Software_Test_Automation_QA
CS 320 Portfolio Item

CS 320: Software Testing, Automation, and Quality Assurance

Throughout this course, I learned how important testing is to making sure software works correctly and meets its requirements. To ensure my code is functional and secure, I focus on validating inputs, testing both expected and unexpected situations, and making sure the program handles errors appropriately. In Project One, I used JUnit tests to verify that the contact, task, and appointment services followed their requirements. I also measured code coverage to identify areas that could benefit from additional testing. This helped me understand that just because a program runs successfully doesn’t necessarily mean it is completely reliable or secure.

When interpreting user needs, I try to break the requirements down into smaller, more manageable pieces and consider how someone will actually use the program. For example, the contact service needed to allow users to add, update, and delete contacts while preventing invalid information from being accepted. Translating those requirements into specific functions and tests helped me make sure the program behaved as intended.

My approach to designing software is to start by understanding what the program needs to accomplish before deciding how to build it. I prefer to work through individual components, test them as I go, and make adjustments when I find problems. This course reinforced the importance of considering potential errors early in development rather than waiting until the program is finished. Going forward, I want to continue using these practices to create software that is reliable, maintainable, and easier to improve over time.
